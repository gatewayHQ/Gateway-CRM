# Installable app (PWA)

Agents can install Gateway CRM on a phone, tablet or computer. It opens full screen
from its own icon, with no browser bar. It is still the same site on the same Vercel
deploy, so there is nothing to publish to an app store and every deploy reaches
installed copies on their next launch.

## How it fits together

```
                       ┌────────────────────── index.html (no-store) ─────────────────────┐
                       │  favicon, apple-touch-icon, theme-color  (static, every page)    │
                       └──────────────────────────────┬───────────────────────────────────┘
                                                      │
                                 src/main.jsx picks a view from the path
                                ┌─────────────────────┴──────────────────────┐
                    public page (/lp/*, /portal/*,                      agent app (<App />)
                    /advisor/*, /u/*, /lead …)                                  │
                    → nothing below happens                    enableInstallableApp()  src/lib/pwa.js
                                                                ├─ <link rel=manifest> → public/manifest.webmanifest
                                                                ├─ iOS app meta tags
                                                                ├─ capture beforeinstallprompt
                                                                └─ register /sw.js  (production builds only)
                                                                                │
                                                     <InstallPrompt />  src/components/InstallPrompt.jsx
                                                     "Install" (Chrome/Edge/Android) or
                                                     "Share → Add to Home Screen" (iOS)

 public/sw.js, for every request from a page it controls:
   page navigation ............ network; on failure → /offline.html   (index.html is never cached)
   /assets/* (hashed) ......... cache-first, capped at 250 entries
   /brand/*, /icons/*, font CSS  stale-while-revalidate
   fonts.gstatic.com .......... cache-first
   everything else ............ untouched: /api/*, /m/*, /e/*, /share/*, /u/*, Supabase,
                                BoldSign, CDNs, any non-GET or Range request
```

### Why only the agent app is installable

The same `index.html` serves the client-facing pages. If the manifest lived in
`index.html`, a buyer who saved a listing to their home screen would get an icon that
opens the agents' login. So `main.jsx` enables the PWA only when it is about to render
`<App />`.

### Why the app shell is never cached

`vercel.json` serves `index.html` as `no-store` so that every deploy reaches everyone
right away. A service worker that cached the shell would quietly undo that. Here the
cache is used only for files whose URL changes whenever their content does (Vite's
hashed `/assets/*`), plus the brand art and fonts. This is also why the worker can
`skipWaiting()` right away: nothing it serves belongs to a particular build.

### Why some paths are passed through untouched

| Path | Why the worker never touches it |
| --- | --- |
| `/api/*` | Live data, authenticated, often POST. Also carries the Outlook OAuth callback, a one-time code that must be exchanged exactly once. |
| `/m/*`, `/e/*` | QR-scan and email-open trackers. Every hit has to reach the server to be counted. |
| `/share/*`, `/u/*` | Rendered on the server. |
| Other origins | Supabase, BoldSign, the pdf.js CDN. Their own caching rules apply. |

Navigation preload is deliberately **off**. With it on, the browser would send those
passthrough navigations twice.

## Database and API

Nothing changed. Installing the app is entirely on the client: it uses the existing
Supabase session and the existing `/api/*` functions unchanged. On iOS the installed
app keeps storage separate from Safari, so agents sign in once more after installing.

## Files

| File | Role |
| --- | --- |
| `public/manifest.webmanifest` | App name, colours, icons, `display: standalone` |
| `public/sw.js` | Service worker (routing rules above) |
| `public/offline.html` | Shown when a navigation fails for lack of network. Self-contained. |
| `public/icons/` | Generated by `scripts/build-brand-assets.mjs` (see `public/brand/README.md`) |
| `src/lib/pwa.js` | Enables the PWA, registers the worker, install-prompt state |
| `src/components/InstallPrompt.jsx` | The "Install Gateway CRM" card (snoozes 30 days on dismiss) |
| `vercel.json`, `docker/nginx.conf` | `sw.js` and the manifest served `no-cache` |
| `src/lib/__tests__/serviceWorker.test.js` | Runs the real `sw.js` against a fake worker global |
| `src/lib/__tests__/pwa.test.js` | When the install card may show |

## Operating it

**Normal deploys need no change to `sw.js`.** Bump `VERSION` in `sw.js` only if the
caching rules change shape. Old `gw-*` caches are deleted when the new worker activates.

**Check it in production:** Chrome DevTools → Application → Manifest (no errors, icons
shown) and → Service workers (`/sw.js` activated). Lighthouse's PWA checks should pass.

**Emergency: remove the service worker.** If the worker ever misbehaves, replace the
whole of `public/sw.js` with the code below and deploy. Browsers re-check `sw.js` on
every navigation (it is served `no-cache` and registered with
`updateViaCache: 'none'`), so each installed copy picks it up on its next load, clears
its caches and unregisters:

```js
self.addEventListener('install', () => self.skipWaiting())
self.addEventListener('activate', (e) => e.waitUntil((async () => {
  for (const n of await caches.keys()) await caches.delete(n)
  await self.registration.unregister()
})()))
```

## Deliberately left out of this version

- **Push notifications.** The next step, and the main reason to go further. Needs VAPID
  keys, a `push_subscriptions` table (`agent_id`, `endpoint`, `p256dh`, `auth`,
  `user_agent`, `created_at`, unique on `endpoint`, RLS by agent), an `/api/push`
  subscribe/unsubscribe action, and a sender (the `web-push` package) called from the
  places that already write `agent_notifications`. On iOS it only works once the app is
  installed (16.4+).
- **Offline data.** The CRM's data lives in Supabase behind RLS. Caching it on devices
  would mean syncing and resolving conflicts, and client PII left on lost phones. Not
  worth it for an app used online.
- **App shortcuts** (long-press icon → Tasks, Pipeline). The app has no URL routing apart
  from `?deal=`, so this would need new deep-link params first.
- **App Store / Play Store listing.** Would need Capacitor. The PWA gives most of the
  value without the review process.
